## 구현 동작

OBSERVED 화면에 들어가면 목록과 선택한 실행 상세를 조회하고 완료 후 약 1초 뒤 다시 조회한다. 동시에 두 갱신 작업을 진행하지 않으며 연속 수동 새로고침은 한 번의 후속 작업으로 합친다. 조회는 8초 후 취소 신호를 보내고 네트워크 오류는 1/2/4/8/10초 간격으로 재시도한다. 401/403 및 수집기 없는 404에서는 자동 재시도를 멈춘다. 이는 SSE/WebSocket 스트리밍이 아니다.

새 trace가 추가되어도 현재 선택을 바꾸지 않는다. 상세 데이터가 같으면 소스 DOM을 유지하고, 데이터가 바뀌면 manifest/definition이 정확히 일치하는 함수만 재선택한다. 보관되지 않은 과거 소스를 현재 파일로 대체하지 않는다. 최신 목록 100개에서 빠진 선택 trace도 상세 API로 확인하며 실제 만료/삭제 404일 때만 선택을 해제한다.

자동 갱신 중지/시작과 수동 새로고침을 제공한다. 중지는 화면의 주기 조회만 멈추며 실제 앱·DB·수집기는 계속 동작한다. OBSERVED 화면 이탈, 비활성 문서, pagehide에서는 진행 요청을 취소하고 주기 조회를 멈춘다. 화면 복귀는 현재 상태 확인을 위한 조회를 수행한다. 인증 실패는 화면에 보관한 trace/소스를 제거하고 새 로그인 링크를 안내한다. 네트워크 오류는 마지막 성공 시각과 오래된 정보일 수 있다는 경고를 표시한다.

삭제 확인 후 진행 중인 조회를 취소하고 삭제 결과가 확인되면 기록/소스를 비운다. 삭제 응답이 불명확하면 자동으로 DELETE를 다시 보내지 않고 수동 조회를 안내한다. 삭제 중 늦게 도착한 조회 결과를 적용하지 않는다.
